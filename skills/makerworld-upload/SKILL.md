# MakerWorld 上传

完成实际上传，核对保存结果，交付准确的草稿或发布链接。只生成文案不等于上传完成。

## 默认走脚本，不逐项探索网页

1. 用 `scripts/prepare.py` 生成本地发布清单；自动检查 3MF、盘数、文件哈希并保存照片。输入标题、说明文件、分类、标签和照片即可：

```bash
python3 scripts/prepare.py --file /path/final.3mf --photo /path/real-photo.jpg \
  --title '模型标题' --description-file /path/description.txt --category '地理' \
  --tag '地形' --output /path/publication
```

2. 自动上传器为 `scripts/upload.mjs`，清单是 `publication.json`。默认保存草稿，持久化草稿 URL、媒体上传进度及结果；续跑同一清单。已上传媒体不重复发送，文件变化则报错。
3. 优先在当前已登录的 Codex 浏览器中导入模块并调用 `runFromManifest(tab, '/absolute/publication.json', '/absolute/proof.jpg')`，复用工具提供的 Tab API；这仍经浏览器授权 API 操作，没有读取 cookies。读取当前工具说明，模块导入使用其支持的 Node REPL 能力。
4. 独立 CLI 可用 `node scripts/upload.mjs /path/publication.json --login` 打开专用浏览器，首次正常登录后关闭，再去掉 `--login` 执行。需要 Playwright；可用 `MAKERWORLD_PLAYWRIGHT_MODULE` 指向已安装模块。不擅自接管个人 Chrome 配置或复制登录信息。
5. 脚本覆盖 3MF、标题、分类、标签、实拍、封面、保存、重开核验、截图。**当前自动化到草稿，不含打印配置编辑或最终发布**；只有真实跑通相应页面后才能增补适配器，不虚构表单或宣称已自动发布。上传器保留现有许可证和可见性，不代签协议。
6. 表单变更或校验失败时停止固定流程，观察对应异常一次、修正适配器再续跑。不把每次任务变成重新浏览全站。

## 文件、账号与素材

- 从项目的最终导出记录、用户确认及实际文件确定版本，不按文件名或修改时间盲选。保持多盘工程的布局、配色、对象设置、公差和试配盘；不为上传自动重新切片、缩放、修复或换机型。
- 可运行 `python3 scripts/inspect_3mf.py /绝对路径/model.3mf` 只读核对 ZIP 完整性、SHA256、机器、耗材、填充、擦料塔、对象和盘数。元数据检查不证明水密、床面范围或实机效果。
- 优先使用现成连接器；没有上传接口时通过当前可用浏览器 UI 操作并读取工具文档。不要提取 cookies 或凭据，也不要用独立 Playwright 接管登录会话。
- 保留用户选择的站点和账号，不自动同步全球站。Chrome 登录不等于内置浏览器已登录。原生 Chrome 被用户切页打断时重新观察；持续冲突则改用内置浏览器登录，不反复争抢窗口。
- 文案讲用途、尺寸、组件、打印方法、拼装方法及真实验证范围。数值来自最终工程或切片记录；时间及克数估算标为估算。多色明确全工程颜色数、单盘颜色数和 AMS 槽映射，耗材编号不是 AMS 槽号。
- 小样或部分零件照片只证明相应部分，不声称完整套件已验证。不把渲染、AI 图、同一照片的裁剪复制当成多个真实视图。真实照片同时用于封面和实拍栏，不增加视图数量。
- 根据当前表单核对封面、实物图、其他模型图、视频与文档的各自用途及限制；不要把曾经观察到的限制当永久规则。
- 有已知来源许可疑点时准备其他内容并明确待核实项，不把公开可下载写成 Public Domain，也不靠禁止商业使用假定解决了上游许可。地图类另核对平台版图规则和官方参考，不凭保留源几何声称官方核验完成。

## 表单与保存

1. 找到同模型的已有草稿并续填、保留 ID；遇到其他作品草稿不要覆盖。为当前模型只新建一次，恢复时不重复上传。
2. 如实选择原创或二创、Bambu Studio 文件、激光及 CyberBrick 类型。已有 3MF 不为省事换 STL；原始附件只使用最终版本。
3. 使用当前工具的文件选择器 API 上传绝对路径，核对文件名和上传完成状态。接受文件不证明平台识别了全部盘；打印配置页应核对盘数。
4. 填标题、分类、标签和富文本描述。分类搜索后选择实际可见选项；标签逐个 Enter 并核对实际保存数。富文本使用纯文本或明确的 HTML 粘贴，不让 Markdown 标记原样留在正文。
5. 上传照片和封面并确认裁剪及完成状态。保持用户指定的可见性及许可，未决定的授权不擅自扩成商业、独家或跨站分享；表单默认值也需核对。
6. 保存后重开同一草稿，检查标题、介绍、分类、照片和附件是否保留。不要仅凭点击按钮报告成功。
7. 用户要求发布且资料齐备时完成发布，不重复请求笼统许可。工具要求签署协议等具体操作前确认时，停在该操作，展示协议和具体动作。
8. 照片不足、文件解析或页面校验失败时，保存有效草稿并报告页面原文与缺项；不凑照片或修改页面绕过校验。恢复时继续原草稿。

## 交付

区分已上传文件、草稿已保存、已提交审核与已公开发布，只有观察到对应状态才这样描述。交付真实链接及草稿或模型 ID，按工具文档保存并展示能核验状态的截图。单次发布完成后不自动监控审核或发其他平台帖子。

必要时查官方依据，以实时页面为准：

- 中国站社区准则（含地图要求）：https://makerworld.com.cn/zh/community-guidelines
- 模型上传准则：https://wiki.bambulab.com/zh/makerworld/tutorials/model-upload-guidelines
- 打印配置实拍及完整性要求：https://wiki.bambulab.com/zh/makerworld/tutorials/print-profile-upload
